# Microsoft onboarding concern — preliminary assessment, 2026-10-05

Owner: expired Azure secret and manual admin steps undermine Maelle cloneability/usability for ordinary users. Product design concern; no authentication redesign implementation authorized.

Current source: src/connectors/graph/graphClient.ts uses ClientSecretCredential (app-only) with global AZURE_TENANT_ID/CLIENT_ID/CLIENT_SECRET. src/config/index.ts requires secret. src/connectors/graph/mail.ts refreshAccessToken also requires that secret for delegated mailbox refresh. README Setup requires app registration and a separately signed-in assistant mailbox. Calendar read/mutation calls use /users/{email}, so switching authentication requires capability/identity review rather than replacing a credential alone.

Direction to evaluate: user-facing Connect Microsoft sign-in; separate application operator responsibilities from end-user consent; least-privileged delegated owner calendar access and availability where supported; explain restricted capabilities/admin-consent requirement; credential/reconnection health with bounded notifications. Hosted multitenant service versus independent self-hosted clones remains an architectural choice; do not distribute one confidential application secret among clones. Public-client flows cannot contain a client secret, but require an appropriate app registration and do not bypass tenant policy. No claim all existing capabilities will work unchanged.

Official sources checked 2026-10-05:
- https://learn.microsoft.com/en-us/entra/identity-platform/permissions-consent-overview : delegated access operates within user's rights; app-only permissions require admin consent.
- https://learn.microsoft.com/en-us/entra/identity-platform/msal-client-applications : public clients cannot hold client secrets; confidential server apps can.
- https://learn.microsoft.com/en-us/graph/api/calendar-getschedule?view=graph-rest-1.0 : organizational delegated free/busy access supported with Calendars.ReadBasic; personal Microsoft accounts unsupported for this API.
- https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/configure-user-consent : organization controls user consent.

This is a bounded source/documentation assessment, not a tested design or production change. It does not establish that a Global Administrator specifically is required for all setup steps. Admin consent and ongoing secret management are distinct concerns.
