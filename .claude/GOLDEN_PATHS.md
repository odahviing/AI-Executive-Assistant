# Golden paths — the 30 behaviors that must never silently break

**What this is.** A fixed battery of short, few-step, paper-traceable checks over Maelle's ordinary golden-path behaviors — the unit-test floor under every wave. It exists because a shipped guard change (CLASS 2, 2026-08-30) passed two adversarial verify passes and still deterministically broke the most common colleague flow: both passes traced only "is the incident now caught," never "does the ordinary case still work." This file is the standing answer to the second question. It is NOT `test-scenarios.md` (owner-authored multi-turn stories, run on demand) and NOT the `trace` skill (which GENERATES scenarios from a fresh diff) — it is the same 30 checks, every verify pass, unconditionally.

## How to run (this header is the whole law — no other copy exists)

- **Paper only.** No live DMs, no calendar/DB writes, no tool calls against the running system. Reading source files is the only side effect.
- **Run every item, every time.** No sampling, no skipping items whose files "obviously didn't change" — unconditional is the design, decided over a diff-triggered alternative on 2026-08-30.
- **Per item: open the anchors, walk the trace, compare to `expect`.** One verdict each:
  - `pass` — the code on disk still delivers the expected behavior. When an item's anchor file was touched by the wave under review, quote the anchor's current load-bearing line in your evidence; otherwise a one-line confirmation suffices.
  - `fail` — the behavior breaks at HEAD. REQUIRED: `file:line` where it breaks, plus the item's `lane`. **A fail is an overturn** — in a wave it routes to the owning lane through the bounce ladder; at a wrap it blocks the wrap.
  - `stale-anchor` — the behavior is intact but a cited anchor has drifted (moved lines, renamed symbol). REQUIRED: where it actually lives now. Reported for re-pinning, never blocks. (`scripts/check-stale-citations.cjs` also sweeps these anchors at every wrap.)
- **Return one entry per item plus `itemsInFile`** (your own count of `Z\d+` items in this file) so a shortfall is arithmetic, not judgment.
- **Honesty about LLM links:** where an item's outcome depends on a model reading a prompt (not on code structure), trace the structural half and say plainly which half rests on the model — never grade that half `pass` by assumption.

**Admission rule.** An item must be traceable in ~3 hops or fewer through one subsystem. Anything longer is a scenario, not battery material — it belongs in `test-scenarios.md` or a one-off `trace` run. **Growth by admission, never to a number:** a new item is minted when a high-impact incident closes (the incident IS the scenario) or a genuinely-daily path is identified. Item content is product spec — the owner approves adds and removals; anchor re-pinning is maintenance and needs nobody's sign-off.
